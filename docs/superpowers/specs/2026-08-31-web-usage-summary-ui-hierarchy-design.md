# Web Token 用量页三级明细视觉与信息架构设计

## 设计状态

已获用户确认，进入开发实现阶段（2026-08-31）。本设计是在一期用量统计页基础上的 UI 和交互修正，不改变后端接口、聚合口径、权限边界或缓存策略。

## 目标

让 Web 控制台的用量页与 Chrome 插件的真实信息架构一致，并沿用数据看板的视觉层级：

```text
API 令牌汇总 → 选中 API 令牌 → 渠道汇总 → 选中渠道 → 模型汇总
```

页面顶部的总览卡片和趋势信息可以跨令牌汇总，但任何明细列表都不得把渠道或模型混入 API 令牌一级维度。

## 参考实现

本次交互依据 Chrome 插件仓库的实际实现，而不是照搬插件的请求机制：

- `src/sidepanel/sidepanel.html`：一级表格标题为“按 API 令牌”。
- `src/sidepanel/sidepanel.js` 的 `renderRows()`：点击令牌后更新当前令牌并重置渠道选择。
- `src/sidepanel/sidepanel.js` 的 `renderDetail()`：在当前令牌上下文中展示渠道；选择渠道后渲染“渠道内按模型”。
- `src/sidepanel/detail-state.js`：默认选择按总 Token 排序后的第一个渠道，并保持模型只属于渠道。

Web 页面只复用数据层的 Token → 渠道 → 模型归一化结果，不引入插件源码、Content Script、Cookie 或缓存。

## 页面结构

1. 顶部标题、时间范围、权限范围和刷新操作。
2. 五项总览卡片：请求数、输入 Token、输出 Token、总 Token、quota。
3. 用量趋势与“API 令牌分布”辅助面板；分布面板只按 API 令牌计算占比。
4. “按 API 令牌汇总”表格：每行一个 API 令牌，点击后进入该令牌明细。
5. 当前令牌明细卡：
   - 当前令牌卡片显示令牌名称并标明“渠道汇总”；
   - 渠道汇总列表可点击；默认选中当前令牌总 Token 最高的渠道；
   - 下方“渠道内模型汇总”只渲染当前选中渠道的模型，不显示跨渠道模型汇总。

## 交互和状态

- API 令牌表格使用语义化按钮/可操作行，并暴露 `aria-selected`。
- 点击 API 令牌只改变本地选择，不重新请求接口；切换令牌时渠道选择重置为该令牌第一个渠道。
- 点击渠道只更新当前渠道和下方模型表，不改变 API 令牌和查询范围。
- Token、渠道、模型均按 `totalTokens` 降序，默认首项即最高消耗项。
- 空 Token、空渠道、空模型分别显示明确的空状态；加载、错误和已有缓存状态继续沿用一期页面行为。

## 数字显示

- 大数使用中文紧凑单位：`1.24亿`、`3,684万`、`12.86万`、`1.2千`。
- 详情表格和总览卡片保留完整数值到 `title` 属性，便于核对。
- 原始 `quota` 仍按现有页面格式化规则显示，不在本次 UI 改造中自行推导人民币或美元。

## 兼容与边界

- 不修改 Go 后端聚合接口、数据库、Docker Compose、生产镜像或 `usage-logs` 页面。
- 不改变 `/api/log/usage-summary` 和 `/api/log/self/usage-summary` 的请求参数及权限选择。
- 只修改 `web/src/features/usage-summary/` 的组件/格式化逻辑、对应测试，以及本设计/发布记录。
- 生产环境不参与本地开发预览和测试；正式镜像切换仍须另行审批。

## 验收标准

- 页面上可明确看到“按 API 令牌汇总”，不再出现含义不清的“按 Token 汇总”。
- API 令牌表格不显示渠道或模型列作为一级维度。
- 选中 API 令牌后只显示它的渠道；选中渠道后只显示该渠道的模型。
- 切换令牌/渠道不会增加聚合接口请求次数。
- 大数字显示中文单位，悬停能取得完整值。
- 现有用量页的加载、空数据、错误、管理员/普通用户权限和 API 请求测试继续通过。
